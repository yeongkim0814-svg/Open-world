# 스타일 개편 설계서 — 큰 실루엣·색면·대기 원근 (Compatibility)

> 상태: 승인된 설계 (2026-10-11) · 지침: `docs/GRAPHICS_IMPLEMENTATION_GUIDE.md` · 대체 대상: `docs/design/03-art-direction.md` v0.2(실사풍)
> 게임 제목은 가제(프로젝트 이름 "Open World" 유지). 문서에서는 "본 게임".

## 1. 배경과 목표

실사풍 개편(v0.2) 결과 세 문제가 남았다.

| 문제 | 원인 |
|---|---|
| 식생이 징그럽다 | 뾰족한 카드형 풀잎이 고밀도로 고르게 깔리고 실사 질감과 섞여 "털"처럼 보임 |
| 절벽에 반복 무늬 | 같은 바위 사진 텍스처를 삼면 투영으로 반복 — 사진 텍스처는 반복이 필연적으로 보임 |
| 건축물이 도형 같다 | 형태는 상자 그대로, 표면만 실사 |

**목표:** Omno의 원리(큰 실루엣, 단순한 색면, 높이 안개, 절제된 조명)를 참고해 본 게임만의 스타일을 만든다. Omno 고유 에셋·캐릭터·구조물·맵 배치는 복제하지 않는다.

**성공 기준** (지침 9장 체크리스트 + 아래)
- 위 세 문제가 테스트 씬 스크린샷에서 해소됨 (사진 텍스처 0, 반복 무늬 없음, 풀은 덩어리로 읽힘)
- 고갈 ↔ 회복이 한눈에 구분됨
- 웹(Compatibility) 빌드와 태블릿 Godot 에디터 실행 모두 오류 없음, 태블릿 60 FPS 목표 / 45 하한
- 기존 게임플레이(등반·수영·전투) 회귀 없음 — 테스트 184개 + 등반 스윕 유지

## 3. Omno 분석 요약

출처: Jonas Manke 인터뷰 *Omno: Tips on Low Poly Indie Game Creation* (80.lv, 2017) 원문 확인 = **[원문]**. 리뷰 요약·원리 추론 = **[추정]**.

- **철학 [원문]:** "세계는 거대하게, 에셋은 최대한 단순하게." 상자형 나무 숲 + 바위 몇 개 + 로우폴리 풀 + 높이 안개 + 후처리(피사계 심도·색 보정)만으로 분위기를 냈다.
- **작업 순서 [원문]:** 빈 씬에서 하늘색 → 후처리 색 → 높이 안개 → 큰 블록 지형 → 게임플레이 → 메시 교체·식생·빛. 분위기와 큰 형태가 디테일보다 먼저.
- **하늘 [원문]:** 천정색은 어둡게, 지평선까지의 색 변화 폭은 좁게(진한 하늘이 지배), 지평선은 밝게 해서 구름·안개와 섞음.
- **안개 [원문]:** 지수 높이 안개는 "거의 필수". 높이 감쇠를 크게, 안개 원점을 낮게 → 플레이 영역 아래 안개층.
- **구름 [원문]:** 로우폴리 구름 메시 + 노이즈 정점 애니메이션. 가까운 구름은 정점을 많이, 먼 구름은 LOD.
- **대비 [원문]:** 세계는 각진 평면 음영, 주인공만 부드러운 음영 → 시각적 긴장, 주인공이 읽힘.
- **바위 [원문 일부·추정]:** 아시아 탑 모양 바위 지형에서 영감, 큰 블록에서 출발. 단색에 가까운 면 + 약한 노이즈 색 변주 [추정].
- **식생 [추정]:** 덩어리형 나무·로우폴리 풀·바람 흔들림. 잎을 개별로 표현하지 않음.
- **물·건축:** 자료 없음 → 지침 원칙으로 독자 설계.

## 4. 렌더링 (Compatibility)

- `project.godot`: `rendering_method = "gl_compatibility"` (+ `.mobile`). Forward+ 전용 설정(SSAO·SSIL·볼류메트릭 안개·SDFGI·화면 공간 반사)은 쓰지 않는다.
- 해 `DirectionalLight3D` 1개, 그림자 거리 약 60m, PSSM 2분할. 환경광 = 하늘 그라데이션.
- 거리 안개 + 높이 안개(Environment 기본 fog — Compatibility 지원). 안개색 = 하늘 지평선색.
- 톤매핑 Filmic, 약한 글로우(생명 에너지·코어만 HDR 초과).
- **틈새 그늘(AO) 대체:** 메시 생성 시 정점색 알파(또는 정점색 명도)에 오목함·지면 접촉 그늘을 굽는다.
- 깊이 텍스처를 읽지 않는다(웹 호환·비용). 물가 표현은 높이 지도로 미리 계산.

## 6. 구조

### 6.1 공통 색면 셰이더 `shaders/style_lit.gdshader`
- 입력: 기본색(고갈/회복 두 벌), 정점색(명도·AO), `recovery_map` 샘플.
- 큰 크기 월드 노이즈(값 노이즈, 수십 m 주기)로 명도 ±5~8% — 반복 무늬가 생기지 않는 저주파만.
- 평면 음영 옵션: `flat = true`면 `dFdx/dFdy` 면 법선 사용 (메시를 따로 쪼개지 않아도 됨).
- `roughness` 높게, `metallic` 0. 노멀맵·사진 텍스처 없음.
- 지형용 `style_terrain.gdshader`는 같은 include(`style_common.gdshaderinc`)를 쓰고 경사·높이 색 띠를 더한다.

### 6.2 회복 데이터
- `scripts/core/recovery.gd` (RefCounted, 노드 비의존, TDD)
  - `Region`: id, 중심, 반경, `recovery` 0~1, `stage()` → `DEPLETED`(<0.3) / `REGENERATING` / `RESTORED`(=1).
  - 과제 기여 API: `add_progress(region, amount)` — 탑 외 과제 합계는 `TASK_CAP`(기본 0.4)에서 멈춤. `neutralize_tower(region)` → 1.0.
  - `to_dict` / `from_dict` (저장/불러오기).
- `scripts/nodes/recovery_map.gd`: 지역 목록 → **저해상도 회복 지도 텍스처**(예: 128×128, 월드 범위 매핑)를 갱신해 전역 셰이더 변수 `recovery_map`·`recovery_map_rect`로 넘긴다. 값 변화는 시간 보간(갑자기 바뀌지 않음). 임의 모양·개수의 지역을 셰이더 변경 없이 지원.
- 하늘·안개처럼 위치 없는 요소는 "플레이어가 있는 지역의 recovery"를 보간해 쓴다.
- 기존 `vitality_*` 전역 변수는 첫 섬 통합 단계에서 회복 지도로 교체한다(그 전까지 공존).

### 6.3 코드 생성 에셋 (`scripts/core/gen/`, 결정적 시드)
| 생성기 | 형태 규칙 | 예산 |
|---|---|---|
| `rock_gen.gd` | 정이십면체 → 저주파 변형·평면 깎기(단면) → 평면 음영. 변형 3~5종(둥근 바위·판석·기둥형) | 40~200 삼각형 |
| `tree_gen.gd` | 줄기(각진 원기둥) + 큰 잎 덩어리 2~4개(변형 다면체), 높이·기울기·색 변주 | 150~400 |
| `grass_gen.gd` | 둥근 덩어리형 풀(삼각형 6~10개, 끝이 넓은 꽃잎형 — 뾰족한 털 금지) 2~3종 | 6~10 |
| `structure_gen.gd` | 모서리 깎은 블록·계단·기둥·아치, 높이·폭·파손(모서리 떨어짐) 변주 | 부품당 12~200 |
| `cloud_gen.gd` | 뭉친 다면체 구름 덩어리 | 100~300 |

- 모든 생성기는 정점색에 AO·명도 변주를 굽는다.
- 배치: 풀·작은 바위 = `MultiMeshInstance3D`(청크), 큰 바위·나무·구조물 = 소수 노드 또는 MultiMesh. 배치 밀도 = 노이즈 군집 × recovery(풀·꽃은 회복 시 증가).
- 바람: 풀·잎 정점 셰이더에서 아주 약한 흔들림(정점색으로 뿌리 고정).
- 구름: 정점 노이즈 움직임, 거리에 따라 단순 메시.

### 6.4 지형
- 높이 지도·충돌·등반 규칙은 유지(게임플레이 기반).
- 보이는 메시만 교체: 색 띠(풀밭 / 흙길 / 절벽 바위색 / 모래), 평면 음영 vs 부드러운 음영을 테스트 씬에서 비교 후 결정.
- 절벽 가장자리에 큰 바위 덩어리를 배치해 실루엣을 만든다(충돌은 단순 모양, 등반 스윕 재확인).

### 6.5 물·하늘·원경
- 물: 단색 + 얕음/깊음 색(높이 지도로 정점 단위 깊이 계산) + 약한 파문 노멀 + 하늘색 프레넬. 알파 블렌드 1장.
- 하늘: 그라데이션 셰이더(천정 진하게, 지평선 좁고 밝게), 해 원반. 사진·FBM 전체 화면 구름 없음 → 비용 감소.
- 원경: 능선 링(색면) + 낮은 구름층, 공기 원근으로 하늘에 녹임.

### 6.6 건축
- 부품 씬(블록·계단·기둥·아치) 조합. 큰 실루엣 먼저, 중간 디테일(받침·띠·파손)은 가까이서만.
- 무광 돌색, 오래된 느낌은 명도 얼룩·파손 형태로. 발광은 생명 에너지·코어만.

## 7. 테스트 씬 `scenes/style_test.tscn`

- 작은 섬(약 128m) 하나: 코드 생성 높이 지도(언덕·절벽·협곡·작은 호수), 대표 에셋 바위 3·식생 3·건축 3, 하늘·조명·안개.
- 디버그 UI: recovery 슬라이더(0~1), 평면/부드러운 음영 토글, 안개 토글, FPS·그리기 호출·정점 수 표시.

- 스크린샷 도구(`tools/shots.sh`)에 `style_test` 시점 추가: 근경·중경·원경 × 고갈/회복.

## 8. 단계 (지침 7장)

1. 렌더러 전환 + 테스트 씬 골격(하늘·조명·안개·팔레트) → 기존 씬이 Compatibility에서 깨지는 곳 목록화
2. 공통 색면 셰이더 + 대표 에셋(바위 3·식생 3·건축 3) 생성기
3. 배치(MultiMesh 청크, 군집 노이즈)·원거리 단순화·성능 측정
4. 회복 모델·회복 지도 + 슬라이더 연결
5. 첫 섬 통합(지형 셰이더 교체, 바위·풀·구조물 교체, vitality → 회복 지도) → 실사 에셋 삭제
6. 웹 내보내기·태블릿 확인(Chrome, Godot 에디터)

각 단계 끝: `./run_tests.sh`, 헤드리스 실행 오류 로그 0, 스크린샷 검토, 수정 파일·결과 보고.

## 9. 테스트

- **단위(TDD):** 생성기 — 결정성(같은 시드 = 같은 메시), 삼각형 예산, 바깥 방향 법선, 정점색 범위. 회복 모델 — 단계 구간, 과제 상한(탑 외 합계 ≤ TASK_CAP), 탑 무력화 = 1.0, 저장/불러오기 왕복. 회복 지도 — 지역 안/밖 값, 보간 수렴.
- **회귀:** 기존 184개 테스트, 등반 스윕(134/135 이상), 경로·탑·호수 탐침.
- **시각:** 스크린샷 대조 시트 + 검토 에이전트(사진 텍스처 0, 반복 무늬, 풀 인상, 실루엣 가독성, 고갈/회복 구분).
- **성능:** 테스트 씬·첫 섬 4시점에서 그리기 호출·정점 수(헤드리스 측정), 태블릿 FPS(사용자).

## 10. 위험·열린 질문

1. 웹에서 지형 생성 시간 증가(데스크톱 약 1초 → 웹 3~5초 예상) — 필요 시 생성 결과 캐시(.res) 또는 분할 생성.
2. 웹 빌드를 태블릿 Chrome에서 여는 경로(이 컨테이너에서 내보내기 → 호스팅 방식) — 6단계 전에 상의.
3. 지형 평면 음영: 1m 격자는 면이 너무 잘아 지저분할 수 있음 → 테스트 씬에서 비교 후 결정.
4. 회복 기여 수치(과제별 %), 마을 회복 조건 — 탑·마을 설계 때 결정. 이 설계는 불변 조건만 고정.
5. Compatibility에서 기존 셰이더(물 DEPTH_TEXTURE 등) 동작 차이 — 1단계에서 목록화.
