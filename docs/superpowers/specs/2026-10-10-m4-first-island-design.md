# M4 '첫 섬' 설계서 — 루프 한 바퀴

> 상태: 합의됨 (2026-10-10 논의) · 상위 문서: `docs/design/01-core-design.md`, `02-combat-design.md`
> 그래픽 방향은 `docs/design/03-art-direction.md`(작성 예정)를 따른다. 이 문서는 게임 내용과 기술 구조만 정한다.

## 1. 목표와 범위

**목표:** 2시간 루프(설계서 01 4.2)를 처음으로 끝까지 체험한다 — 마을의 사정을 듣고 → 섬을 탐험해 수문을 열고 → 저수호를 건너 탑을 올라 → 탑을 멈추면 섬이 회복되고 마을의 운명이 정해진다.

**핵심 질문 (태블릿 검증):**
1. 지시 없이 수문 3곳을 스스로 찾아가는가? (기둥 3)
2. 수문을 열수록 탑 접근이 쉬워지는 것이 "마을을 돕는 이유"로 느껴지는가?
3. 탑 정지와 회색→컬러 전환이 보상으로 충분히 강렬한가?

**포함:** 새 씬 `first_island.tscn`(높이 지도 지형), 저수호·수문 3곳·수위 변화, 탑 등반·코어 정지, 회색→컬러 전환, 수호 기계 배치와 정지, 마을 「마른샘」 주민 5명·대화, 마을 결과 3단계, 대장장이 수리, 자동 저장, 시작 장면.

**제외 (M5 이후):** 원소(불·바람·젖음)·날씨, 시련, 지도 UI, 낮·밤, 요리·인벤토리, 엔딩, 무기 추가, 보스.

## 2. 결정 로그

| # | 질문 | 결정 |
|---|---|---|
| W1 | M4 범위 | 루프 한 바퀴 (지도·마을·적응 퀘스트·탑 정지) |
| W2 | 적응 퀘스트 | 물 → 고대 수로의 수문 3곳 복구 |

**탑 접근 장치 후보 (이후 지역 탑에 배분):** 저수호 해자(첫 탑) · 맥동 외벽(주기적 생명력 맥동, 홈에 피하거나 타이밍 등반) · 흡입구 봉인(섬 곳곳 흡입구 3개를 끊어야 코어 보호막 해제) · 회색 장막(탑 반경 안 스태미나 회복 불가, 쉼터 샘에서만 회복).

## 3. 이야기

**물의 흐름 (세계 설정):** 섬의 물은 원래 북쪽 산의 샘에서 고대 수로를 타고 남쪽으로 흘렀다. 고대인은 수문 3곳을 닫아 물을 섬 중앙 저수호로 돌리고 그 한가운데 착취탑을 세웠다. 지금 마을 「마른샘」은 탑에서 새어 나오는 생명력으로 우물에서 겨우 물을 긷는다. 수문을 열면 물이 마을로 돌아가고, 저수호로 드는 물이 줄어 수위가 내려간다.

**시작 장면 (컷신 없음, 연출만):** 마른샘 광장에서 시작. 탑의 소용돌이가 10초간 멈칫하고, 그 사이 마을 주변에 색이 번졌다가 다시 회색으로 돌아간다. 촌장: "…방금 봤느냐. 탑이 멈추면 땅이 숨을 쉰다. 하지만 우물도 마르겠지." → 촌장과 대화하면 수로 이야기, 노인 이야기꾼은 수문 위치를 옛이야기로 알려준다 (마커 없음, 기둥 3).

**결과 (탑을 멈춘 순간 열린 수문 수):**

| 열린 수문 | 결과 | 마을 |
|---|---|---|
| 3 | 번영 | 우물이 넘치고 마을 이름이 「샘골」로 바뀜. 주민 5명. 수리 부품 1 |
| 1~2 | 버팀 | 우물이 얕음. 아이 가족이 떠날 준비(대사). 주민 5명. 수리 부품 1 |
| 0 | 쇠퇴 | 우물이 마름. 아이·우물지기가 떠남(주민 3명). 수리 부품 2 |

- 정지 후에도 수문을 열 수 있다: 우물·대사는 한 단계씩 나아지지만 **떠난 주민은 돌아오지 않는다.** 결과 등급은 정지 순간 값으로 고정해 엔딩(A/B 장면)이 읽는다.

## 4. 지도 (300m × 300m, 북쪽 = −Z)

```
              [북쪽 산 · 샘]
           수문1 (30m 바위벽 위)
 수문2                                수문3
 (서쪽 협곡 —      ┌─────────┐       (동남쪽 소규모 거점:
  활공으로 건넘)   │ 저수호  │        칼날형 2 + 포격형 1)
                   │  ▲ 탑   │
                   └────┬────┘
              고대 수로 ═╝
              [마른샘 마을]
              [남쪽 해변 · 바다]
```

- **수문 1 (등반):** 북쪽 산 중턱, 30m 바위벽 위. 스태미나를 나눠 쓰는 경로(중간 턱)가 있다.
- **수문 2 (활공):** 서쪽 협곡 건너편. 높은 쪽에서 뛰어 활공해야 닿는다. 아래로 돌아가는 긴 길(헤엄+등반)도 존재.
- **수문 3 (전투):** 동남쪽. 칼날형 2기 + 포격형 1기가 지키는 소규모 거점.
- **저수호 (압도감):** 반경 약 45m의 호수를 높이 16m의 **고대 둑**이 둘러싼다. 초기 수면 **14.6m** — 마을(3m)보다 11m 이상 높아, 마을에서 올려다보면 둑이 물을 막고 그 위로 탑이 솟는다. 바닥 −4m(수심 약 18m). 수문 1개당 **−3.9m** (14.6 → 10.7 → 6.8 → 2.9), 내려갈수록 둑 안쪽에 물때가 드러난다. 둑길(남쪽 둑 → 탑 섬) 윗면 3.2m — 3개 열면 드러나 걸어서 건넌다. 둑길 선의 **돌기둥 2개**(윗면 11.0m·7.1m)가 수위에 따라 차례로 드러나 쉼터가 된다(열수록 헤엄 거리 단축). 탑 섬은 바위 기둥(윗면 18m). 탑 섬 기슭 포격형 1기 (헤엄 중엔 방어 불가 → 위협).
- **탑:** 높이 60m, **계단식 4단**(15m마다 폭 1.5~2m의 단 = 쉼터, 서 있으면 스태미나 회복 — 기본 스태미나로 연속 등반 한계가 약 20m이므로). 탑 밑 칼날형 1기, 40m 쉼터 칼날형 1기. 꼭대기 코어 = 상호작용 「정지」.
- **마을 마른샘:** 남쪽 저지대, 해변과 저수호 사이. 집 6채 + 광장 우물 + 대장간 + 촌장 집. 고대 수로가 북쪽에서 마을 우물로 이어진다.
- 연쇄 장치(설계서 01 4.2): 각 수문에서 다음 목표(다른 수문 또는 탑)가 최소 1개 보이게 배치.

## 5. 시스템과 기술 구조

### 5.1 노드 비의존 모델 (`scripts/core/`, 헤드리스 테스트)

| 모델 | 책임 | 인터페이스 요지 |
|---|---|---|
| `HeightField` | 높이 지도 샘플링 | `_init(image: Image, world_size: float, min_h: float, max_h: float)`, `height_at(x, z) -> float`(쌍선형), `normal_at(x, z) -> Vector3` |
| `WorldState` | 진행 상태 | `sluices: Array[bool]`(3), `tower_stopped: bool`, `outcome_at_stop: int`(−1 = 미정), `departed: Array[StringName]`, `open_sluice(i)`, `stop_tower()`, `open_count()`, `to_dict()/from_dict()` |
| `LakeLevel` | 수위 | `static level(base_y: float, open_count: int, drop := 3.9) -> float` |
| `VillageOutcome` | 결과 등급 | `enum Tier { THRIVE, ENDURE, DECLINE }`, `static tier(open_count) -> Tier`, `static repair_cost(tier) -> int`, `static departing(tier) -> Array[StringName]` |
| `DialoguePicker` | 대사 선택 | `static pick(table: Dictionary, npc: StringName, state: WorldState) -> PackedStringArray` — 조건이 가장 구체적인 항목 우선 |
| `SaveGame` | 저장 | `static save(path, data: Dictionary) -> bool`, `static load(path) -> Dictionary`(없거나 손상 → `{}`) |

### 5.2 노드 (`scripts/nodes/`)

- `TerrainBuilder` (Node3D): `HeightField`로 ArrayMesh(2m 격자, 약 4.5만 삼각형) + `HeightMapShape3D` 생성. 공용 회복 셰이더 재질 사용.
- `Sluice` (상호작용 「수문 열기」): 열면 `WorldState` 갱신 → 저수호 수위 이동(수 초에 걸쳐) → 수로 물 표시 → 자동 저장.
- `Lake`: 기존 `Water` 영역 + 수면 메시. 목표 수위로 천천히 이동.
- `TowerCore` (상호작용 「정지」): 소용돌이 입자 정지 → 생명력 터짐 입자 → 회복 반경 확장 → 섬의 기계 `deactivate()` → 결과 확정 → 자동 저장.
- `Villager` (상호작용 「대화: 이름」): `DialoguePicker`로 대사를 받아 말풍선 표시(탭으로 넘김). 결과에 따라 떠난 주민은 숨김.
- `Blacksmith`: `Villager` + 수리 (기존 `RepairBench` 규칙, 비용 = `VillageOutcome.repair_cost`).
- `Machine`: `deactivate()` 추가 (정지 시 멈추고 회색 처리, 부활 없음).
- `FirstIsland` (씬 루트 스크립트): 시작 장면 연출, 저장 불러오기·적용, 자동 저장 트리거(마을 진입·수문·탑 정지).

### 5.3 회색 → 컬러 전환

- 지형·소품 공용 spatial 셰이더 + 전역 셰이더 변수 `vitality_center: vec3`, `vitality_radius: float`. 반경 밖 = 채도 낮춤(회색), 안 = 원래 색. 경계는 부드럽게(약 10m).
- 탑 정지: 반경 0 → 섬 전체(약 220m)를 6초에 걸쳐 확장. 시작 장면의 "숨 쉬는 땅"은 마을 중심 반경 30m를 잠깐 열었다 닫는 같은 장치.
- 구체 색·스타일은 `03-art-direction.md`에서 정한다.

### 5.4 기존 시스템 변경

- **등반 규칙 (구현 반영):** 지형 경사 **60°까지는 걸어서** 오르고(`floor_max_angle` 60°), **60°보다 가파르면 등반**한다 — 미끄럼 구간 없음. 등반은 벽면을 따라 위로 움직이고(경사면에서 떨어지지 않게), 이동 방향과 벽의 각 비교는 수평 성분끼리 한다. 올라서기 도약 중에는 착지할 때까지 다음 벽을 잡지 않는다(계단식 탑).
- **안전 지점:** 물에 잠긴 곳 제외 (M3 이후 반영 완료).

### 5.5 대사 데이터

`dialogue/marunsaem.json` — 주민별 항목 목록. 항목 = `{ "when": {조건}, "lines": [...] }`. 조건 키: `open_min`, `open_max`, `stopped`, `tier`. 조건을 모두 만족하는 항목 중 조건 수가 가장 많은 것을 고른다(같으면 먼저 쓴 것).

## 6. 작업 단위

- **M4a 세계:** 높이 지도 지형 + 등반 규칙 보정, 지도 배치(산·협곡·저수호·탑·둑길·마을 자리), 저수호·수문·수위, 탑 등반·쉼터·코어 정지, 회색→컬러 전환·소용돌이, 기계 배치·정지.
- **M4b 마을:** 주민 5명·대화·말풍선, 결과 3단계·떠남·이름 변경, 대장장이, 자동 저장/불러오기, 시작 장면.

## 7. 검증

- **자동 테스트:** `HeightField` 샘플링(모서리·경계), `LakeLevel`, `VillageOutcome`(0·1·2·3개), `DialoguePicker`(구체적 조건 우선, 해당 없음), `SaveGame` 왕복·손상 파일, `WorldState` 직렬화.
- **섬 시뮬레이션:** (a) 수문 3개 열기 → 둑길 위를 걸어 탑 도달, (b) 탑 등반 → 정지 → 결과 번영·주민 5명, (c) 수문 0개 정지 → 쇠퇴·주민 3명·수리 2, (d) 정지 후 수문 열기 → 우물 단계만 개선, (e) 저장 → 재시작 → 상태 복원.
- **태블릿:** 지형 + 입자 + 기계가 있는 장면 FPS (목표 60, 하한 30), 루프 체감 확인 양식 `docs/perf/m4-check.md`.

## 8. 위험

- **높이 지도 지형의 등반감:** 2m 격자 경사는 울퉁불퉁해 벽 감지가 흔들릴 수 있다 → 등반 경로의 주요 벽은 상자 도형으로 보장.
- **지형 생성 시간:** 시작할 때 약 2.3만 정점 생성 — 태블릿에서 1초 넘으면 생성한 메시를 리소스로 저장하는 방식으로 전환.
- **전역 셰이더 변수:** Android 에디터에서 프로젝트 설정의 전역 셰이더 변수가 동작하는지 M4a 첫 작업에서 확인.
