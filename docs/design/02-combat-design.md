## 2. 조작 체계 (터치 기준 초안)

```
 ┌─────────────────────────────────────────────┐
 │ [HP/스태미나]                    [무기 휠]  │
 │                                             │
 │                                    (락온)   │
 │   ◯ 가상 스틱                  (회피) (공격)│
 │   (이동)                     (패링)  (강공) │
 │              화면 드래그 = 카메라           │
 └─────────────────────────────────────────────┘
```

- **오른손 4버튼 원칙:** 공격 · 강공격 · 회피 · 패링. 그 이상은 휠/길게 누르기로 처리.
- **락온:** 탭 = 가장 가까운 적 고정 / 스와이프 = 대상 전환. 터치에서 카메라와 공격을 동시에 다루기 어렵기 때문에 **락온은 필수 기능**.
- **무기 교체:** 휠(전투 중 슬로우 없음 — 긴장 유지). 즐겨찾기 3칸 퀵슬롯.
- 모든 버튼 위치·크기는 설정에서 조정 가능하게.

## 3. 회피와 패링

### 3.1 회피 (기본 방어)
- 구르기/대시, 스태미나 소모. 동작 초반 **무적 시간 약 0.3초** (터치 기준; 실측 후 조정).
- **저스트 회피:** 공격 적중 직전 회피 시 짧은 반격 창(강공격 즉시 발동) — 회피 중심 리듬의 보상.

### 3.2 패링 (보너스)
- 적은 패링 가능한 공격 직전 **뚜렷한 예고 신호**(무기 섬광 + 효과음)를 낸다. 패링 불가 공격은 다른 색 신호(회피 강제).
- 패링 버튼 판정 창: **신호 후 약 0.25초** (터치 기준, 패드 정밀 모드는 더 좁게).
- 실패 시: 패링 자세 경직으로 큰 피해 → 위험 부담.

### 3.3 패링 보상: 슬로우모션 연타
- 성공 → 적만 느려지는 **약 1.5초의 집중 시간**, 공격 버튼 연타로 연속 공격.
- 구현 원칙: 전역 `Engine.time_scale`을 쓰지 않고 **적 개체별 시간 배율**로 처리 → 플레이어 조작감·UI·물리 판정에 영향 없음. 판정은 `_physics_process` 고정 틱에서.

## 4. 무기

### 4.1 무기 종류 (목표 7종+)

| 단계 | 무기 | 성격 |
|---|---|---|
| 프로토타입 | 한손검 | 빠름, 기본 |
| 프로토타입 | 대검 | 느림, 강한 경직·장갑 파괴 |
| 프로토타입 | 활 | 원거리, 약점 저격 |
| 확장 | 창 | 긴 사거리, 찌르기 — 틈새 약점 |
| 확장 | 쌍검 | 매우 빠른 연타, 낮은 단발 피해 |
| 확장 | 망치/둔기 | 기계 장갑 특화 |
| 확장 | 도끼 | 벌목·환경 파괴 겸용 |
| 확장 후보 | 방패 계열, 투척 무기 등 | 논의 필요 |

### 4.2 같은 종류 내 차별화
- 수치(공격력·속도·내구도), **원소 부여**(불·바람 — 상호작용 시스템과 동일 규칙), 특수 효과.

### 4.3 비용 통제 원칙
- 이동·회피·피격 애니메이션은 **전 무기 공유**, 무기별로는 공격 세트만 추가.
- 애니메이션 조달: CC0 라이브러리(예: Quaternius) + Godot에서 타이밍 조정.
- 무기는 **데이터 리소스**(`WeaponData.tres`)로 정의: 콤보 단계, 판정 프레임, 경직, 패링 가능 여부, 내구도. 새 무기 = 대부분 파일 추가.

### 4.4 내구도와 수리
- 사용 시 내구도 감소, 0이 되면 **파손 상태**(사라지지 않음, 성능 대폭 저하).
- 수리: 마을 대장장이 + **기계 부품**(수호 기계 처치 보상). 마을이 쇠퇴하면 수리 불가/비용 증가.

## 5. 적: 수호 기계

- 디자인 언어: 고대 착취 시스템의 부속. 몸체의 **발광 코어**가 약점, 장갑 부위는 무기 상성에 따라 효율 차이.
- 예고 신호 색 규칙 (전 적 공통):
  - 🟡 노란 섬광 = 패링 가능
  - 🔴 붉은 섬광 = 패링 불가, 회피만
- 탑과 연결: 탑이 멈추면 그 지역 기계도 정지 → 회복 이후 지역은 평화로워짐.

## 6. 전투 형태와 도입 단계

| 형태 | 설명 | 도입 시점 |
|---|---|---|
| 소수 정예 | 1~3기, 패턴 읽기·패링 중심 | **프로토타입** |
| 거점 | 다수 기계가 지키는 요새, 원소·지형으로 침투 경로 다양 | **프로토타입** (소규모 1곳) |
| 탑 보스전 | 각 착취탑의 최종 수호자, 연출 있는 보스 | 프로토타입 직후 (첫 확장) |
| 거대 기계 | 움직이는 거대 기계에 등반해 약점 파괴 | 등반 시스템 안정화 후 (확장) |
