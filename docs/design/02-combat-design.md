## 2. 조작 체계 (터치 기준 — C10~C12 반영)

```
 ┌─────────────────────────────────────────────┐
 │ [HP/스태미나]                    [무기 휠]  │
 │                                             │
 │                                             │
 │   ◯ 가상 스틱                  (점프/회피)  │
 │   (위로 끌기 = 자동 달리기)  (방어)  (공격) │
 │     화면 드래그 = 카메라 / 적 탭 = 고정     │
 └─────────────────────────────────────────────┘
```

| 입력 | 평상시 | 전투 상태 (경계 중인 적이 근처) |
|---|---|---|
| 스틱 | 60% 미만 = **걷기**(스태미나 0, 바라보는 방향 유지) / 60% 이상 = **달리기**(스태미나 소모, 이동 방향으로 회전) / 위로 끌어 🔒에서 놓기 = **자동 달리기** | 이동 |
| 공격 | 상호작용(줍기·대화·탑 조작)으로 바뀜 | 탭 = 공격, **길게 = 강공격** |
| 방어 | — (숨김) | **누르는 순간 = 패링 판정**, 누르고 있으면 = 방어 자세 |
| 점프/회피 | 점프 · 등반 점프 · 공중에서 활공 | **스틱 방향 + 버튼 = 회피** (방향 없으면 백스텝). 적중 직전이면 저스트 회피 |

- **버튼 3개 원칙:** 공격 · 방어 · 점프/회피. 기능은 버튼을 늘리지 않고 *상황*과 *누르는 방식(탭/길게/타이밍)*으로 확장한다.
- **보이는 문맥:** 버튼의 의미가 바뀌면 아이콘이 즉시 바뀐다 (점프 ↔ 회피, 공격 ↔ 상호작용). 플레이어가 지금 이 버튼이 무엇을 하는지 항상 알 수 있어야 한다.
- **동시 누르기 조합 지양:** 터치에는 촉감이 없어 두 버튼을 정확히 동시에 누르기 어렵다. 조합이 필요하면 *스틱 + 버튼 하나*까지만.
- **조준 (C10):** 공격은 카메라 방향·거리 기준 가장 적합한 적에게 자동으로 향한다. 현재 대상에 외곽선 이펙트. 정밀 조준(거대 기계 약점·활)은 **화면의 적을 탭해 고정**, 다시 탭하거나 멀어지면 해제.
- **바라보기 규칙:** 걷기 = 방향 유지(옆·뒤 이동) / 달리기 = 이동 방향으로 회전 / 오른손으로 시점 조작 중 = 유지 / 자동 달리기 = 항상 이동 방향 / 등반 = 벽. 락온 없이도 적을 바라본 채 거리를 조절할 수 있다 (기둥 4).
- **자동 등반:** 걷기·달리기(직접·자동) 중 벽에 닿으면 자동으로 오른다. 단 이동 방향과 벽 정면의 각이 **40° 이내**일 때만 (벽을 옆에 끼고 이동할 때는 오르지 않음). 자동 달리기는 등반 시작 시 해제된다.
- **무기 교체:** 휠(전투 중 슬로우 없음 — 긴장 유지). 즐겨찾기 3칸 퀵슬롯.
- 모든 버튼 위치·크기는 설정에서 조정 가능하게.

### 2.1 전투 상태 (C12·C14)

**진입·해제**
- 진입: 플레이어를 발견(경계)한 적이 **15m** 안에 있을 때, 또는 플레이어가 공격하거나 공격받았을 때.
- 해제: 경계 중인 적이 **25m** 안에 **3초** 동안 없을 때. 진입·해제 거리를 달리해 경계선에서 상태가 깜빡이지 않게 한다.

**전투 상태에서 바뀌는 것**
| 항목 | 평상시 | 전투 상태 |
|---|---|---|
| 버튼 | 점프 / 상호작용 | 회피 / 공격 (C12) |
| 바라보기 | 걷기 = 유지, 달리기 = 이동 방향 (2장) | 이동 방향으로 회전 (걷기 포함) |
| 카메라 | 자유 (오른손 드래그) | **캐릭터 등 뒤로 자동 정렬** (C14) |
| 자동 달리기 | 사용 가능 | 진입 시 해제 |

**카메라 자동 정렬 완화 규칙 (터치에서 화면이 손가락과 싸우지 않게)**
- 오른손이 화면(카메라 영역)을 누르고 있는 동안에는 자동 정렬을 멈춘다. 손을 떼고 **0.5초** 뒤부터 다시 따라간다.
- 정렬은 즉시 회전이 아니라 부드럽게 (초당 약 180°, 실측 후 조정).
- **회피 동작 중에는 정렬하지 않는다.** 회피마다 화면이 휙 돌면 멀미와 방향 상실을 부른다.
- 진입 순간에는 약 0.3초에 걸쳐 한 번 등 뒤로 맞춘다.
- 적을 탭해 고정(C10)했을 때는 캐릭터가 그 적을 바라보고, 카메라는 캐릭터 등 뒤를 유지하므로 적이 화면 중앙 쪽에 담긴다.

**구현 시점:** M2 첫 작업 (적이 있어야 검증 가능).

## 3. 회피와 패링

### 3.1 회피 (기본 방어)
- 구르기/대시, 스태미나 소모. 동작 초반 **무적 시간 약 0.3초** (터치 기준; 실측 후 조정).
- **저스트 회피:** 공격 적중 직전 회피 시 짧은 반격 창(강공격 즉시 발동) — 회피 중심 리듬의 보상.

### 3.2 패링 (보너스)
- 적은 패링 가능한 공격 직전 **뚜렷한 예고 신호**(무기 섬광 + 효과음)를 낸다. 패링 불가 공격은 다른 색 신호(회피 강제).
- **방어 버튼을 누르는 순간**이 신호 후 판정 창(약 0.25초, 패드 정밀 모드는 더 좁게) 안이면 패링. 누른 채 유지하면 방어 자세.
- **연타 방지:** 판정은 누르는 순간에만. 1초 안에 반복해 누를수록 판정 창이 줄어든다.
- 🔴 신호 공격을 방어 자세로 받으면 **가드 브레이크**(긴 경직) → 회피 강제.
- 실패 시: 패링 자세 경직으로 큰 피해 → 위험 부담.

### 3.3 패링 수단 (C7)
| | 무기 패링 | 방패 패링 | 방패 막기 |
|---|---|---|---|
| 조건 | 모든 무기, 방어 버튼 누르는 순간 | 방패 장착, 방어 버튼 누르는 순간 | 방어 버튼 유지 (무기 또는 방패) |
| 판정 창 | 좁음 (~0.2초) | 넓음 (~0.35초) | 상시 (스태미나 소모) |
| 연타 보상 | 길고 무기 고유 동작 | 짧음 | 없음 |
| 막기 피해 | — | — | 방패: 대부분 흡수 / 무기: 일부 관통 + 무기 내구도 크게 소모 |
| 내구도 | 무기 소모 | 방패 소모 | 방패 크게 소모 |

### 3.4 패링 보상: 슬로우모션 연타
- 성공 → 적만 느려지는 **약 1.5초의 집중 시간**, 공격 버튼 연타로 연속 공격.
- 구현 원칙: 전역 `Engine.time_scale`을 쓰지 않고 **적 개체별 시간 배율**로 처리 → 플레이어 조작감·UI·물리 판정에 영향 없음. 판정은 `_physics_process` 고정 틱에서.

## 4. 무기

### 4.1 무기 종류 (목표 7종+)

| 단계 | 무기 | 성격 |
|---|---|---|
| 프로토타입 | 한손검 | 빠름, 기본 |
| 프로토타입 | 대검 | 느림, 강한 경직·장갑 파괴 |
| 프로토타입 | 활 | 원거리, 약점 저격 |
| 확장 | 창 | 긴 사거리, 찌르기 — 틈새 약점 |
| 확장 | 쌍검 | 매우 빠른 연타, 낮은 단발 피해 |
| 확장 | 망치/둔기 | 기계 장갑 특화 |
| 확장 | 도끼 | 벌목·환경 파괴 겸용 |
| 확장 후보 | 방패 계열, 투척 무기 등 | 논의 필요 |

### 4.2 같은 종류 내 차별화
- 수치(공격력·속도·내구도), **원소 부여**(불·바람 — 상호작용 시스템과 동일 규칙), 특수 효과.

### 4.3 비용 통제 원칙
- 이동·회피·피격 애니메이션은 **전 무기 공유**, 무기별로는 공격 세트만 추가.
- 애니메이션 조달: CC0 라이브러리(예: Quaternius) + Godot에서 타이밍 조정.
- 무기는 **데이터 리소스**(`WeaponData.tres`)로 정의: 콤보 단계, 판정 프레임, 경직, 패링 가능 여부, 내구도. 새 무기 = 대부분 파일 추가.

### 4.4 내구도와 수리
- 사용 시 내구도 감소, 0이 되면 **파손 상태**(사라지지 않음, 성능 대폭 저하).
- 수리: 마을 대장장이 + **기계 부품**(수호 기계 처치 보상). 마을이 쇠퇴하면 수리 불가/비용 증가.

## 5. 적: 수호 기계

- 디자인 언어: 고대 착취 시스템의 부속. 몸체의 **발광 코어**가 약점, 장갑 부위는 무기 상성에 따라 효율 차이.
- 예고 신호 색 규칙 (전 적 공통):
  - 🟡 노란 섬광 = 패링 가능
  - 🔴 붉은 섬광 = 패링 불가, 회피만
- 탑과 연결: 탑이 멈추면 그 지역 기계도 정지 → 회복 이후 지역은 평화로워짐.

### 5.1 원소 × 기계 반응 (C9 — `01-core-design.md` 7장 규칙표에 추가)

| 원인 \ 기계 상태 | 일반 | 과열 (불) | 젖음 |
|---|---|---|---|
| **불** | 과열 누적 → 과열 상태 | 과열 중 공격 속도↑·자기 피해 | 불 무효 |
| **물/젖음** | 젖음 상태 | **급냉 균열** → 장갑 방어력 대폭↓ | — |
| **바람** | 가벼운 기계 넘어뜨림 / 투사체 궤도 휨 | 과열 확산 (주변 풀 착화) | 젖음 상태 빨리 마름 |

- 환경 활용 예: 거점 주변 풀에 불 → 연기·혼란으로 잠입 / 불길 상승기류로 활공 기습 / 비 오는 날은 불 공략 불가 → 다른 해법 필요.
- 원칙: 기계·플레이어·환경 모두 **같은 규칙** (01 문서 7장 설계 규칙 유지).
