## 1. 하이 컨셉 (확정)

**가제: 『Open World』** (임시 — 추후 결정)

> 조상이 세계에서 빼앗은 생명력에 기대어 사는 후손이,
> 그 착취 장치를 하나씩 멈춰 세계를 되살리고 —
> 동시에 사람들이 그 힘 없이도 살아갈 길을 찾는다.

- **한 문장 판매 포인트:** "탑을 멈출 때마다 세계에 색이 돌아온다. 그 대가는 내가 지켜야 할 사람들이 치른다."
- **플레이어 감정 목표:** 호기심 → 발견 → 회복의 기쁨 → 그 대가에 대한 책임감 → (엔딩) 상실과 회복의 여운.

## 2. 세계관과 스토리 (확정)

### 2.0 스토리 결정 로그

| # | 질문 | 결정 | 파생 효과 |
|---|---|---|---|
| S1 | 엔딩 감정 | **상실과 회복** | 진행 = 회복. 단, 완전한 회복은 경계 (여운 확보) |
| S2 | 잃은 것 | **세계의 생명력** | 회복을 지역 색·물·생물의 귀환으로 시각화 (팔레트 전환) |
| S3 | 상실 원인 | **사람(고대 문명)이 빼앗았다** | 적 = 아직 작동하는 착취 장치의 수호 기계. 빼앗긴 생명력은 저장되어 있음 |
| S4 | 주인공 | **현재를 사는 후손** | 조상의 죄를 물려받은 세대. 생존자 마을·NPC와의 유대 |
| S5 | 현재 사회 | **알면서도 그 힘에 의존** | 핵심 갈등: 세계의 회복 ↔ 마을의 생존 |
| S6 | 선택 구조 | **적응 퀘스트 + 최종 선택(A/B)** | 분기는 엔딩 1회로 제한 → 1인 개발 범위 통제 |

### 2.1 배경
- 고대 문명은 대지 곳곳에 **착취탑**을 세워 땅의 생명력을 빨아들였고, 그 힘으로 영원할 것 같은 번영을 누렸다.
- 생명력을 잃은 땅은 회색으로 바래고, 강이 마르고, 생물이 사라졌다. 결국 문명 자신도 무너졌다.
- 수백 년 뒤. 탑들은 **아직도 작동 중**이다. 빼앗긴 생명력은 세계 중심의 **대저장소**로 흘러가 고여 있다.

### 2.2 현재의 사람들
- 생존자들은 소수의 마을을 이루어 산다. 마을은 **탑에서 새어 나오는 생명력**(빛·온기·작물 성장)에 기대어 버틴다.
- 모두가 조상의 죄를 어렴풋이 알지만, 탑 없이는 살 수 없기에 외면한다.

### 2.3 주인공
- 이 시대를 사는 **평범한 후손.** 탑에 의존하는 마을에서 자랐다.
- 마을의 탑이 고장 나 주변 땅이 잠시 되살아나는 장면을 목격하며 여정을 시작한다 (도입부 후보 — 세부는 스토리 문서에서).

### 2.4 지역 진행 구조 (BotW 탑의 역전)
1. **탐험:** 회색으로 바랜 땅을 가로질러 지역의 착취탑까지 경로를 개척한다.
2. **전투:** 탑에 가까울수록 강해지는 수호 기계를 돌파한다.
3. **적응 퀘스트:** 탑 아래 마을이 탑 없이 살 방법을 마련한다 (물길 복구, 대체 작물, 이주 등).
4. **정지:** 탑을 멈춘다 → 지역에 색·물·생물이 돌아오고, 지도가 열리고, 그 지역 수호 기계가 멈춘다.

- 적응 퀘스트 없이 탑을 끌 수도 있다. 대신 그 마을은 **쇠퇴**한다 (주민 감소, 상점 폐쇄). → *대가가 있는 자유.*

### 2.5 적
- 고대 착취 시스템의 **수호 기계들.** 재질·크기·공격 패턴이 다양하며, 무기 선택이 공략법이 된다 (예: 두꺼운 장갑 → 대검, 틈새 약점 → 창).
- 탑과 연결되어 있어, 탑이 멈추면 그 지역 기계도 멈춘다 → 회복이 전투 환경까지 바꾼다.

### 2.6 최종 선택 (엔딩 2종)
대저장소에 도달한 주인공은 수백 년간 고인 생명력 앞에 선다.
- **(A) 전부 돌려준다:** 세계는 완전히 회복된다. 그러나 고대의 모든 장치, 그리고 그 위에 세워진 사람들의 삶의 기반이 사라진다.
- **(B) 일부를 남긴다:** 회복은 불완전하지만, 사람과 자연이 공존할 기반이 생긴다.
- 설계 원칙: **어느 쪽도 정답이 아니다.** 플레이 중 마을을 얼마나 도왔는지가 각 엔딩의 장면(누가 살아남아 있는가)에 반영된다.

### 2.7 서사 전달 원칙
- **컷신 최소화, 환경 서사 우선.** 폐허·벽화·유품으로 고대의 선택과 몰락을 조각내어 흩뿌린다.
- 마을 NPC의 대화와 변화(번영/쇠퇴)가 플레이어 행동의 거울이 된다.

## 3. 디자인 기둥 (Pillars)

모든 기능은 아래 넷 중 최소 하나를 강화해야 한다. 어느 것도 강화하지 않으면 **만들지 않는다**.

1. **보이면 갈 수 있다 (Freedom of Traversal)**
   벽·절벽·산은 장애물이 아니라 경로다. 등반·활공으로 시야에 든 모든 곳에 도달 가능. 제한은 "불가능"이 아니라 "스태미나·준비 부족"으로만 건다.
2. **규칙이 해법을 만든다 (Systemic Play)**
   퍼즐과 전투에 정답 하나를 두지 않는다. 불·바람·젖음의 일관된 규칙만 주고, 해법은 플레이어가 조합한다.
3. **고요한 발견 (Quiet Discovery)**
   마커·퀘스트 목록으로 끌고 가지 않는다. 랜드마크의 실루엣, 빛, 소리가 플레이어를 부른다. HUD는 최소.

4. **읽고 받아치는 전투 (Readable Combat)**
   적의 공격은 반드시 읽을 수 있는 예비 동작을 가진다. 정확한 타이밍의 패링이 가장 큰 보상을 주고, 무기마다 다른 리듬·사거리로 같은 적도 다르게 상대한다. 원소(기둥 2)는 전투에도 동일하게 적용된다.

> 긴장 관계: 전투 비중이 높으면 '고요한 발견'과 충돌할 수 있다. 원칙 — **전투는 플레이어가 선택해 들어가는 장소(거점·시련·위험 지대)에 밀도 있게 모으고, 이동 구간은 고요하게 유지한다.**

## 4. 핵심 재미와 루프

### 4.1 재미의 원천

| 재미 | 구체 장면 | 담당 기둥 |
|---|---|---|
| 호기심 해소 | 안개 너머 이상한 실루엣 → 가서 확인 | 3 |
| 경로 개척 | "저 절벽, 스태미나 아슬아슬하게 오를 수 있을까?" | 1 |
| 창발적 해법 | 풀에 불 → 상승기류 → 활공으로 적 거점 위 침투 | 2 |
| 긴장감 있는 결투 | 적의 내려치기를 패링 → 빈틈에 대검 강공격 | 4 |
| 가시적 진행 | 탑을 멈추자 회색 땅에 색·물·생물이 번져 나감 | 1, 3 |
| 무게 있는 선택 | 마을을 먼저 도울까, 바로 탑을 멈출까 | — (서사) |

### 4.2 세 겹의 루프

```
[30초 루프]  보기 → 이동(달리기·등반·활공) → 상호작용(채집·원소·전투)
      ↓
[10분 루프]  랜드마크 발견 → 도전(지형/퍼즐/적) → 보상(재료·조각·시련 입장)
      ↓
[2시간 루프] 마을 적응 → 지역 탑 정지 → 세계 회복 + 지도 공개 → 다음 지역으로
```

- **연쇄 장치:** 어떤 보상 지점에 서든 시야에 *다음 호기심 대상이 최소 2개* 보이도록 배치한다 (BotW의 "삼각형 법칙" 응용 — 5장 설계 규칙).

## 5. 플레이어 목표 구조

| 층위 | 목표 | 플레이어가 아는 방식 |
|---|---|---|
| 최종 | 세계 중심 대저장소에 도달해 최종 선택 | 시작 지점에서 지평선 위로 항상 보임 |
| 중기 | 지역 착취탑 정지 + 마을 적응 (지역당 1개) | 작동 중인 탑은 생명력을 빨아들이는 빛줄기로 멀리서 식별 |
| 단기 | 시련(소형 던전) 클리어, 기억 조각 수집, 재료 획득 | 빛·소리 단서로 자연 유도 |

- **순서 자유:** 최종 목표는 처음부터 도전 가능하다(극도로 어렵게). 지역 순서는 강제하지 않는다.

## 6. 성장과 반복 동기

- **성장 축은 '능력'이 아니라 '여유':** 새 행동을 해금하지 않고, 이미 가진 행동의 한계를 늘린다.
  - 시련 클리어 → **빛의 결정** → 4개 모으면 *최대 체력* 또는 *최대 스태미나* +1 선택.
  - 장비(옷)로 환경 저항(추위·더위) 확보 → 접근 가능한 지역이 넓어짐.
- **수집:** 기억 조각(서사), 숨은 '생명의 씨앗'(소규모 발견 보상 — 바위 밑, 나무 꼭대기 등. 심으면 주변이 국소적으로 되살아남).
- **사망 페널티 (약함):** 마지막 체크포인트(정지시킨 탑, 마을, 또는 자동 저장) 부활. 소지품 유지. 실패 비용 = 이동 시간뿐.
- **재방문 동기:** 낮/밤 주기와 날씨로 같은 장소의 해법이 달라짐 (예: 비 오면 불 사용 불가, 등반 미끄러움).

## 7. 상호작용 시스템 (케미스트리) 초안

원소는 **불·바람·젖음** 3개로 시작한다. 규칙은 코드가 아닌 **데이터 표**로 관리해 확장한다.

| 원인 \ 대상 | 풀/나무 | 나무 상자·다리 | 플레이어 | 적 | 공기 |
|---|---|---|---|---|---|
| **불** | 불 번짐(바람 방향 가속) | 연소 → 파괴 | 화상 피해 | 피해 + 공포 상태 | 불 위로 **상승기류** 생성 |
| **바람** | 불 번짐 방향 결정 | 가벼운 물체 밀기 | 활공 가속/방해 | 화살 궤도 휨 | — |
| **젖음 (비·물)** | 불 소화, 착화 불가 | 착화 불가 | 등반 시 미끄러짐 | 불 피해 무효 | — |

- **설계 규칙:** 같은 규칙은 플레이어·적·환경 모두에 예외 없이 적용 (일관성 = 플레이어가 믿고 계획할 수 있음).
- **확장 후보 (프로토타입 이후):** 냉기, 전기, 금속.

### 8.1 수영 규칙 (확정)
- 발이 수면 아래 **1.2m** 이상 잠기면 헤엄 (그보다 얕으면 걸음). 카메라 기준 스틱 방향으로 **2.5 m/s**, 달리기 없음.
- 헤엄치는 동안 스태미나 **초당 5** 소모. 가만히 떠 있으면 소모도 회복도 없다 (물에서는 쉴 수 없음).
- 점프 버튼 = **가속** (0.5초간 5.5 m/s, 스태미나 15). 버튼 이름이 「가속」으로 바뀐다.
- 물에서 탈진하면 가라앉다 **1.5초 뒤 익사** → 마지막 안전 지점(물 밖)에서 다시 시작. 물에 잠긴 곳은 안전 지점이 되지 않는다.
- 물에서 벽으로 헤엄치면 바로 등반, 얕은 곳·경사로에서는 걸어 나온다. 헤엄 중에는 공격·방어 불가.
- 원소 연동(젖음 상태)은 원소 시스템 단계에서.

## 9. 성공 기준 (플레이테스트로 판정)

프로토타입 완료 후 테스터(본인 + 지인 2명 이상)에게 확인:

1. 지시 없이 15분간 스스로 목적지를 정해 움직이는가? (기둥 3)
2. 탑까지 테스터마다 **다른 경로**를 택하는가? (기둥 1)
3. 시련 또는 적 거점을 설계자가 의도하지 않은 방식으로 푼 테스터가 1명 이상 있는가? (기둥 2)
5. 패링 성공이 '짜릿하다'고 느끼는가? 무기를 상황에 따라 바꿔 쓰는가? (기둥 4)
4. "더 하고 싶다 / 다음 섬이 궁금하다"는 반응이 나오는가?

→ 1~3, 5 중 둘 이상 실패하면 월드 확장 전에 해당 기둥을 재설계한다.

## 10. 개발 환경 제약: 태블릿 (Android)

### 10.1 작업 흐름
```
[Claude: 클라우드 세션]  코드·씬 작성 → GitHub push
          ↓
[태블릿 Termux]  git pull  (프로젝트 폴더는 공유 저장소에 위치)
          ↓
[Godot Android 에디터]  같은 폴더 열기 → 실행·플레이테스트·씬 배치
          ↓
[Termux]  변경사항 git commit/push → Claude가 이어서 작업
```
- Godot 공식 문서도 안드로이드 에디터의 Git 연동 수단으로 Termux를 권장한다.
- 텍스트 기반 씬(`.tscn`)·리소스(`.tres`) 사용 → Git 충돌 해결 가능하게 유지.

### 10.2 렌더링 결정 (중요)
- 안드로이드 에디터에서 **Forward+ 렌더러는 심각한 성능 문제로 비권장** → **Mobile 렌더러 채택.**
- 결과적으로 **SDFGI·VoxelGI·볼류메트릭 포그는 사용 불가.** 앞서 분석한 두 데모의 핵심 기법 다수가 빠진다.
- 대체 전략 (셀셰이딩 방향과 오히려 잘 맞음):
  - 간접광 → 셀셰이딩 + **하늘/지면 2색 앰비언트**로 대체 (셀셰이딩은 GI의 부드러운 그라데이션을 원래 많이 버림)
  - 볼류메트릭 포그 → **거리·높이 기반 일반 포그** + 색 그라디언트 (먼 랜드마크 실루엣 연출에 충분)
  - 빛줄기 → 반투명 메시 카드(가짜 god ray), 발광 머티리얼 + Glow
  - Desert Light에서 가져올 것: 단색 머티리얼, 색보정 그라디언트, 노이즈 횃불 깜빡임, 낮밤 애니메이션
### 10.3 성능 목표 (Galaxy Tab S11 Ultra)
- 기준: **Mobile 렌더러, 60 FPS 목표 / 30 FPS 하한**, 3D 해상도 스케일 0.75부터 시작해 실측 후 조정.
- 근거: 패링은 프레임 타이밍에 민감 → 전투 판정은 `_physics_process`(고정 틱)에서 처리해 렌더 FPS 변동과 분리.
- Godot 4.7.2 Android 에디터에서 첫 주에 빈 섬 + 캐릭터로 실측해 목표를 확정한다.

- PC가 생기면 Forward+ 고품질 프리셋을 *추가 옵션*으로 확장 가능 (설계상 막지 않음).
